# CLAUDE.md

DevLog: offline-first mobile PWA. A stopwatch for the selected task (Start / Pause / Resume / Finish; actual vs span time) beside Tasks on an Eisenhower matrix (urgent × important, plus Unsorted), with story points on the Fibonacci scale (1, 2, 3, 5, 8, 13, 21), a Stats screen (daily targets, streaks, 7-day trends, time breakdown, insights), and a standup each morning plus a Friday recap, all on the phone. Offline-first on the device; Google sign-in (required) and a record in the owner's Google Sheet through small Vercel functions. No AI. Vite 7 + Preact 10 + Tailwind 4 + strict TypeScript, deployed on Vercel. Process and standards: [Agentic Coding Style](https://musdev99.github.io/agentic-coding-style) and [BRANCHING.md](https://github.com/MusDev99/agentic-coding-style/blob/main/BRANCHING.md).

## Commands

```bash
npm run dev        # dev server (service worker off); also serves api/* from .env.local (build/dev-api.ts)
npm run build      # production build to dist/
npm run preview    # serve dist/ (service worker on)
npm test           # node --test, Node 22.18+ (runs .ts directly)
npm run verify     # typecheck + tests + build (= CI, run before every commit)
npm run smoke -- <url>   # post-deploy checks (scripts/smoke-checks.ts, tested)
```

## Working loop (every change)

Plan (goal, files, risks; owner approves) → Gather (read code/docs first) → Act (smallest diff on a branch) → Verify (`npm run verify` + real run at 375px, online and offline) → Record (README + CHANGELOG in the same PR). After three failed Verify rounds, stop and re-plan. Feature specs live in `docs/features/<slug>/feature.md`.

## Architecture

- `src/App.tsx` composes the screen; pure logic lives in `src/lib/*.ts` with tests in `tests/` (inject time, never read the clock inside pure code).
- **Tasks stay on the device**: a task is a `Note`: `tag` = status (To do / Doing / Blocked / Done), optional `quadrant` = place (`unsorted` or a quadrant; absent reads as `schedule`; new tasks start `unsorted`), `size` (Fibonacci SP 1, 2, 3, 5, 8, 13, 21; absent reads as 1), `spentMs` (banked stopwatch time) + `startedAt` (while running; at most one task) + `runs` (each finished run's start/end, so stats can date time; time banked before v2.4 has none). `pomodoros` is a legacy v2.2 field, read and ignored. IndexedDB `devlog` / store `notes` (keyPath `id`, index `day`), accessed only through `src/lib/db.ts` (`allNotes` loads everything; it also owns the small `localStorage` keys). Rows are validated with `isNote` on read (corrupt rows skipped). Task rules (`TAGS`, `QUADRANTS`, `PLACES`, `SIZES`, prefixes, `moveNote`, `startTimer` / `stopTimer` / `resetTimer` / `elapsedMs`, max length) live in `src/lib/notes.ts`; never hardcode them elsewhere. `day` = `YYYY-MM-DD` in the user's zone of the last status change (re-sorting quadrants does not count), `createdAt` / `movedAt` / `startedAt` = ISO UTC. No server storage, no analytics.
- **Stopwatch**: per task, one running at a time (Start / Pause / Resume / Finish; a pause is the gap between two runs): `startTimer` stops any other run and makes the task Doing; any status other than Doing stops it; `resetTimer` goes back to 0. Wall clock from `startedAt`, so it survives reloads; the UI ticks once a second only while one runs. `TimerPanel.tsx` shows the selected task (the running one wins; the last pick is a per-device pref). Theme: `data-mode="running"` switches `--color-accent` from coral to teal. Two readings in `src/lib/timing.ts` (`taskTiming`, pure, type-only imports so `api/` can reuse it): **actual** = time the clock ran (span − pauses), **span** = first start → last pause / finish (now while running).
- **Session Tasks**: `src/lib/matrix.ts` (pure, tested: Unsorted then Q1–Q4, open work first then this week's done crossed out in place; Unsorted shows only when it holds tasks or during a drag, older done only in List → Earlier, done/total badge) + `SessionTasks.tsx` / `TaskRow.tsx` (own Start/Stop and elapsed time) / `Composer.tsx` (▶ adds and starts). List or Matrix view (per-device pref via `loadPref` / `savePref`). Drag a row with the mouse (6px threshold) or long-press 350 ms on touch (a swipe still scrolls), dropping on any `data-drop` element; the row menu does every move without dragging. Layout: ≥ 1024px timer and tasks side by side, quadrants 2×2 from 768px, stacked below.
- **Activity calendar + CSV**: `src/lib/calendar.ts` (pure, tested): `calendar` = 12 Monday-first weeks, level 0–4 by focus time against the busiest day (done-only day = 1); `dayTasks` = tasks timed or finished on a day; `reportCsv` builds the report on the device (local times, link URLs in their own column, `csvCell` quotes and neutralises `= + - @` formula cells). `ActivityCalendar.tsx` in Stats: roving-focus grid (arrows move by day / week), prev / next day buttons as the 44px alternative to the small cells, downloads via a Blob (nothing sent).
- **Links in tasks**: `src/lib/links.ts` (pure, tested) finds http(s) URLs in task text (text is stored as typed). Rows show the words as the title (`titleText`) and each link as a chip: Jira → issue key (`SKYIQ-10143`), GitHub → `owner/repo#n`, else a short host/path; links open in a new tab with `noopener noreferrer`, outside the row's select button. Places that cannot hold links (timer chip, mini player, stats, tab title, drag ghost) use `plainText`. The sheet keeps the full text.
- **PWA**: `public/sw.js` + pure routing rules in `public/sw-policy.js` (tested). `/assets/*` and `/icons/*` cache-first, pages network-first with cached shell offline, `/api/*` (none today) and non-GET never cached. Cache lookups use `ignoreVary` (Vite's `crossorigin` assets carry an Origin header the cached `Vary: Origin` responses would refuse, which opened the app blank offline). `build/sw-assets.ts` writes `sw-assets.json` (hashed files to precache). New shell file → add to `SHELL` in `sw.js` (test fails otherwise). Bump `VERSION` when caching rules change. Updates: only the first install skips waiting; later versions wait until the app's "New version ready · Reload" posts `skip-waiting` (`useUpdate` in `src/lib/pwa.ts`), and the app checks for updates each time it comes to the foreground.
- **Installed app**: `manifest.webmanifest` (`id`, standalone, colours = `--color-bg`, shortcuts `?screen=timer|tasks|stats`, `&new=1` focuses the add field; parsed by `launchParams` in `src/lib/launch.ts`). Install button from `beforeinstallprompt` (`useInstall`); iPhone / iPad get a one-time Share → Add to Home Screen hint. Open-task count on the icon (`setBadge`), `navigator.storage.persist()` once tasks exist (`keepStorage` in `db.ts`), haptic tick on Start / Stop, no overscroll bounce in standalone. `tests/pwa.test.ts` guards the manifest, shortcuts and the SW update / Vary rules.
- **Stats**: `src/lib/stats.ts` (pure, tested: `dayStats` dates time by run start in the user zone and points/tasks by done day; `streak` counts back from today or yesterday; `weeklyReview`, `breakdown` by task and quadrant, rule-based `insights` capped at five) + `StatsView.tsx`. Daily targets are **per profile**: rules in `src/lib/targets.ts` (import-free, shared with `api/`; `Targets`, `TARGET_LIMITS`, sheet cell mapping), set in `SettingsDialog.tsx` (native modal `<dialog>`), cached per account by `loadTargets` / `saveTargets` in `db.ts` (`devlog.targets:<email>`; the plain key is the signed-out set and seeds a new profile), and stored in the person's Users row through `GET` / `PUT /api/settings` (`api/_lib/settings-handler.ts`, injected deps; PUT same-origin only). On sign-in and back online: an unconfirmed local change goes up first, a profile with nothing saved adopts the device's set, otherwise the profile wins. "On target" = the day's points reach the SP target.
- **Screens**: phone: a bottom tab bar Timer / Tasks / Stats (thumb reach, safe-area aware; the mini player and toasts sit above it); ≥ 1024px: Focus (timer + tasks side by side) / Stats in the header. The choice is a per-device pref; a shortcut URL wins on launch.
- **Standup**: `ruleStandup(cards, today)` in `src/lib/standup.ts` (pure, tested) + `Reports.tsx` (Standup / Week tabs, rebuilt live, Copy). Yesterday = done/doing cards changed on the last earlier active day; Today = done today + everything in Doing; Blockers = everything in Blocked. No AI, no network: nothing leaves the device.
- **Friday recap**: `src/lib/recap.ts` (pure, tested) + `Reports.tsx` (Week tab, opens first Friday to Sunday); cards changed Monday → today. Rules only, never sent to the server.
- **Sign-in**: Google OIDC (authorization code + PKCE, hand-rolled, Web Crypto only) in `api/_lib/auth.ts` + `api/auth/{login,callback,session}.ts`. Google hosts are fixed constants (`GOOGLE`); `APP_URL` comes from env, never the Host header. Cookies are HMAC-signed with a signed `typ` (session vs OAuth, never interchangeable), `HttpOnly; SameSite=Lax; Secure`; the session carries email, name and the Google profile photo URL (`picture`, only `https://*.googleusercontent.com`, checked by `profilePicture` on the server and `googlePicture` in the browser; the CSP allows just that image host). `Avatar.tsx` falls back to the initial. `ALLOWED_EMAILS` is optional (empty = any verified Google account self-registers). The app only learns `?signin=ok|denied`. Client: `src/Root.tsx` gates the app (`SignIn.tsx`: a landing page with an animated product story built from CSS keyframes in `styles.css` (`settle`, `ring`, `bar`, `badge`, `drift`, `bob`; each 100% frame is the settled scene so reduced motion shows a finished picture) and the official Google "G" from the `google-*` colour tokens), opens straight away for a device that signed in before (cached user in `db.ts`, session checked in the background: `src/lib/session.ts`), and runs local-only when there is no sign-in server (503 / local dev).
- **Google Sheet**: `api/_lib/sheets.ts`: service-account JWT (RS256, Web Crypto) → access token at the fixed `oauth2.googleapis.com/token`, cached per instance; Sheets REST with `valueInputOption=RAW` always (text that looks like a formula stays text). The callback upserts the **Users** tab (`email | name | google_id | registered_at | last_login_at | picture_url | target_tasks | target_points | target_minutes`; a new email appends = registration). A sheet error never blocks sign-in. `ensureTab` writes the header row when empty and appends header cells a newer version added (existing rows untouched).
- **Per-user local data**: `db.ts` `setAccount(email)` switches IndexedDB to `devlog:<email>`; tasks made before sign-in existed are copied once into the first signed-in account (`adoptLegacyTasks`); the old `devlog` DB is kept.
- **Tasks sheet sync**: `POST /api/tasks` (`api/tasks.ts` wires `api/_lib/tasks-handler.ts`, which takes its dependencies injected so tests run it): POST only, configured, same-origin, session, per-user rate limit, sheet configured, ≤ 64 KB, ≤ 50 items, every task `isNote`. Rows come from `taskRow` in `src/lib/timing.ts` (columns `TASK_HEADERS`: start, end, pauses, paused / actual / span minutes and readable actual / span); `user_email` always from the session. `upsertTasks` (sheets.ts) updates by `task_id`, appends new ones, never touches another person's row, and marks deletes `deleted` (rows are never removed). Client: `saveNote` stamps `updatedAt`; the IndexedDB `sync` store (DB v2) keeps each task's synced version and pending deletes; `pending` / `batches` / `backoffMs` in `src/lib/sync.ts` (pure, tested); `useSync` in `src/lib/use-sync.ts` pushes ~2s after changes, on `online` and on return to the foreground, retrying with backoff; `SyncChip.tsx` shows Synced / Syncing / Offline · n waiting / Retry / Sign in again / Sheet not set up.
- **Local API**: `build/dev-api.ts` (Vite plugin, `apply: 'serve'` only) runs the real `api/` handlers under `npm run dev` with env from `.env.local`; `API_ROUTES` must list every function (`tests/dev-api.test.ts` fails otherwise).
- `api/` runs on Vercel as **ES modules**: every relative import ends in **`.js`** (`'../_lib/auth.js'`, `'../src/lib/timing.js'`), because Node needs the extension and Vercel compiles each `.ts` to `.js`; TypeScript and Vite map `.js` back to the `.ts` source. An extensionless import crashes every function (`FUNCTION_INVOCATION_FAILED`). `api/_lib/*` keep no relative imports (so `node --test` loads them directly); `src/` modules used by `api/` have type-only imports. `tests/api-imports.test.ts` enforces both. `src/` and `tests/` import with `.ts` extensions (Node strip-types). Route handlers take `Request` → `Response`; logic that needs the network takes an injected `fetch` so tests never touch Google.
- Golden set: `tests/golden/standup-cases.json`; unit tests check the rules keep every blocker and invent nothing.

## Rules

- Strict TypeScript: no `any`, no `@ts-ignore`. No `dangerouslySetInnerHTML`.
- Design tokens only (`@theme` in `src/styles.css`); no raw hex in components.
- Mobile-first: 375px, no horizontal scroll, touch targets ≥ 44px, respect `prefers-reduced-motion` (the global rule in `styles.css` stops all animation). Apply the [Laws of UX](https://lawsofux.com/) and name the law in the PR.
- Motion and feedback: `press` (squeeze on tap), `state-layer` (hover/press tint), `animate-rise` / `animate-pop` / `animate-glow`. Secondary row actions reveal on hover only where hover exists (`[@media(hover:hover)]`); on touch they stay visible.
- Security headers/CSP live in `vercel.json`. A new external host (API, font, CDN) must be added to the CSP deliberately.
- Secrets only in env (Vercel); never commit `.env*`. Document every variable in `.env.example` and the README. Functions fail closed (503) without them.
- Exact dependency versions; commit `package-lock.json`; `npm audit --omit=dev` before each release.

## Git

Never commit to `main`. Branches `feat/` `fix/` `chore/` `docs/` (agent sessions may use their given `claude/` branch). Conventional Commits for commits and PR titles (checked by `branch-policy.yml`); merged branches are deleted by `branch-cleanup.yml`. Squash merge, one concern per PR, under ~400 changed lines. CI `verify` + `branch-policy` must be green. SemVer tags `vX.Y.Z`.
